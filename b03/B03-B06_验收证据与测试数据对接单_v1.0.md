## 0. 一句话目的

对齐两件事：一是 B06/QA-01 验收所需的**版本有效产物与证据读取接口**；二是 T02 **测试数据和故障夹具**的构造与隔离，确保验收可复现、夹具不绕过门槛。

## 1. B03 向 B06 提供什么

### 1.1 读取接口

| 接口 | 用途 | 约束 |
|---|---|---|
| `get_artifacts_for_task(task_id, *, valid_snapshot_ref)` | 读取任务的候选产物 | 只返回对当前输入快照**版本有效**的产物；无效版本不返回、不静默降级 |
| `list_events(after_event_id, limit)` | 拉取事件链 | 用于复原提交、验收、超时时序；`event_id` 幂等 |
| `get_snapshot(ref)` | 读取输入快照 | 含 `spec_version` / `contract_version` / `plan_version` / 依赖产物校验值 |
| `get_task_state(task_id)` | 读取任务状态（只读） | 验收结论由 B02 写入，B03 不代写 |

### 1.2 Test Evidence 建议字段（写入黑板）

```
test_id        用例编号（如 TC-P02 / TC-ORCH-GATE）
input          输入摘要
expected       预期
actual         实际
env            测试环境
artifact_ref   被测产物引用（含版本）
verdict        PASS / FAIL
snapshot_ref   绑定的输入快照
```

## 2. T02 测试数据样例（请 B06 确认是否覆盖验收用例）

| 类别 | 数据 | 预期结果 |
|---|---|---|
| 合法 | 用户 `u001`/`u002`；失物 `i001`（`lost_at` 带时区）；申请 `c001`（`u002` 认领 `i001`） | T03—T05 正常流程通过 |
| 账号边界 | 重复 `account`（大小写变体）、2 字符、65 字符、含非法字符 | `DUPLICATE_ACCOUNT` / `INVALID_FIELD` |
| 时间边界 | `lost_at` 缺失、空串、非 ISO 8601 | 拒绝且不写入 |
| 认领边界 | 认领自己发布的失物、重复申请、认领不存在对象 | `FORBIDDEN` / `DUPLICATE_CLAIM` / `NOT_FOUND` |
| 隐私 | 公开详情/列表/发布结果中的 `publisher_id`、联系方式、凭据字段 | 均不出现 |
| 编排夹具 | 缺 TC-P02/TC-P03 的缺证据夹具；故意漏检的故障夹具 | `TC-ORCH-GATE` / `TC-ORCH-FAULT`，与主运行隔离 |

## 4. 边界声明

- B03 只提供数据与读取能力，不代写验收结论、不自行宣布测试通过。
- `DUPLICATE_CLAIM` 由唯一约束把并发重复申请转换而来，不是测试脚本模拟结果。
- 测试夹具与正式运行数据隔离；发现回归或输入变更时，已 `SUCCEEDED` 的证据需随快照失效。
