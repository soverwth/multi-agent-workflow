# 通用项目总览

## 目标

本项目不是某一个业务系统的实现，而是一套可复用的多智能体协作开发模型。它把不同系统的领域知识放在适配器层，把需求讨论、任务编排、Agent 协议、版本追踪和质量验收保留为通用基础能力。

## 分层方式

- **平台核心层**：黑板、编排器、任务状态、事件、权限、证据和质量门。
- **Agent 能力层**：角色模板、模型适配、结构化输出解析和失败恢复。
- **领域适配层**：需求模板、领域实体、接口契约、测试数据、术语和展示字段。
- **交付集成层**：项目目录、CI、部署配置、运行说明和领域报告。

校园失物招领系统只属于领域适配层的一个案例。它可以帮助团队验证流程，但不能成为核心接口、核心状态或核心目录的唯一假设。

## 通用约束

1. 需求、设计、契约和任务必须保留版本号。
2. 黑板中的过程状态与领域系统中的业务数据分开保存。
3. Agent 只在授权任务边界内读写，不直接越权修改其他工作块状态。
4. 失败通过结构化事件反馈给编排器，不能用自然语言声明代替证据。
5. 领域或共享接口变更后，必须重新验证受影响产物。
6. 替换模型、提示词或领域 fixture 时，必须重新标记输入版本和验收结果。

## 接入流程

`领域输入 → 领域基线 → 通用任务图 → 领域 Agent 适配 → 独立验收 → 集成发布`

每个领域项目都应提供需求引用、设计规格、接口契约、测试 fixture 和运行说明；平台核心不应依赖某个具体系统的字段或业务状态。
