## 3 C1 接口清单

统一前缀 `/api/v1`；成功为 `{ok:true,data:...}`，失败为 `{ok:false,error:{code,field,message}}`，失败不含 data。

| 操作 | 方法与相对路径 | 请求 | 成功 |
| --- | --- | --- | --- |
| register | POST /auth/register | account、password、nickname | 201 UserView，不自动登录 |
| login | POST /auth/login | account、password | 200 {token,expires_at,user} |
| logout | POST /auth/logout | 无 body | 200 null |
| get_me | GET /me | 无参数 | 200 UserView |
| update_me | PATCH /me | 仅 nickname，必填 | 200 UserView |
| list_my_posts | GET /me/lost-items | page、page_size 可选 | 200 分页 LostView |
| list_my_claims | GET /me/claims | page、page_size 可选 | 200 分页 ClaimView |
| publish_lost | POST /lost-items | name、description、location、lost_at 均必填 | 201 LostView |
| search_lost | GET /lost-items | keyword、location、page、page_size 可选 | 200 分页 LostView |
| get_lost | GET /lost-items/{id} | UUID 路径参数 | 200 LostView |
| create_claim | POST /lost-items/{id}/claims | 路径给出失物 ID；body 仅 statement | 201 ClaimView |

仅注册、登录、搜索、详情允许匿名。其余接口必须提供 `Authorization: Bearer <token>`。认证在 JSON、未知字段、分页或对象查询之前执行；业务写事务中再次核对会话，防止初始认证后撤销仍继续写入。

公开响应精确投影：

- UserView：id、account、nickname、created_at。
- LostView：id、name、description、location、lost_at、status、created_at。
- ClaimView：id、lost_item_id、statement、status、created_at。
- 分页：items、page、page_size、total。

不返回 password_hash、publisher_id、applicant_id、私人联系方式。本人接口仅取会话用户，拒绝 user_id 等额外参数。账号／失物／申请 ID 均在服务端生成 UUID。

## 4 关键行为

字段边界来自 C1：account 3～64，nickname 1～30，name 1～80，description 1～1000，location 1～120，statement 1～500，password 8～128 字符。除密码外去首尾空白；账号仅 ASCII 英文、数字、下划线，按小写存储和查重。密码保留空白，不添加契约之外的复杂度规则。

当前 C1 未禁止 U+0000，本地参考适配器不删除、截断或额外禁止它。SQLiteRepository 在自身每个连接上提供按完整字符数计数的 SQL length，修正 SQLite 原生 TEXT 长度在 NUL 处提前终止的问题，使原有 CHECK 与 Python 校验一致。该设置只影响参考连接，原表、约束和已有数据不需重建；独立 SQLite 连接或实际 B03 数据库不会自动获得这一行为，实际接入仍需验证字符能力。

密码使用随机盐 Argon2id：memory_cost=19456 KiB、time_cost=2、parallelism=1、salt_len=16；相同密码不会产生相同散列。登录使用随机 256 位令牌，SQLite 只保存 SHA-256 摘要。会话自创建满 24 小时失效，退出只撤销当前令牌。错误账号和错误密码统一为 401／UNAUTHENTICATED。

lost_at 不能缺失，不能由当前时间代填。接受 C1 的带时区 ISO 8601 秒／可选三位毫秒形式；校验真实日期、时间和偏移，统一存取 UTC 三位毫秒。created_at 独立来自服务端时钟。纯日期、无时区、null、空字符串、非法日期／偏移都被拒绝，记录保持不变。

搜索关键词对名称或描述作字面包含匹配，英文字母不区分大小写；不解释正则、`%` 或 `_` 通配符。地点去首尾空白后精确匹配，与关键词条件取交集。空过滤返回全部 waiting 信息。分页默认 1／20，page_size 最大 100；非法值返回 400。超出末页保留真实 total，items 为空，包括极大的有效页码。列表按 created_at、id 均降序稳定排序。

认领的顺序为字段 → 对象存在 → 本人权限 → waiting 状态 → 重复检查 → 插入，后五步在同一个写事务中执行。禁止认领自己的信息；重复约束为 `(lost_item_id, applicant_id)`，数据库并发唯一约束失败同样映射 DUPLICATE_CLAIM。只创建 pending 申请，不增加确认、驳回、完成或其他未定义 API。

## 5 错误和事务

| code | HTTP | field |
| --- | --- | --- |
| REQUIRED_FIELD | 400 | 缺失字段 |
| INVALID_FIELD | 400 | 无效字段；JSON／整体请求无效时 null |
| UNAUTHENTICATED | 401 | null |
| FORBIDDEN | 403 | null |
| NOT_FOUND | 404 | null |
| DUPLICATE_ACCOUNT | 409 | account |
| DUPLICATE_CLAIM | 409 | lost_item_id |
| INVALID_STATE | 409 | status |
| INTERNAL_ERROR | 500 | null |

未知字段、重复 query 参数、非法 JSON／非对象、类型和字段边界错误都明确拒绝。无效 UUID 为 400，合法但不存在的 UUID 为 404。未预期存储异常在事务内回滚，客户端不接收堆栈、SQL、路径、密码或底层异常信息。

框架 HTTP 异常也遵守 C1：服务端 5xx、无码或无法分类的异常统一为 500／INTERNAL_ERROR；已知请求、认证和路由异常分别映射为 C1 的 400／401／403／404。通用 HTTP 409 不足以判断具体业务冲突，适配器必须明确转换成相应 ApiError；原有 DUPLICATE_ACCOUNT、DUPLICATE_CLAIM、INVALID_STATE 保持各自 409 语义。

SQLite 参考适配器使用外键、账号唯一约束、申请复合唯一约束及写事务；数据访问参数绑定，不拼接用户输入为 SQL。失物状态检查和认领插入不可拆成两个可交错事务；T02 适配器也必须保持这一语义。
